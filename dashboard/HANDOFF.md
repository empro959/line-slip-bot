## 3. Data model

**`pos_daily.json`** (รายวันดิบ):
```
[{ date:"2026-07-10", period:"กรกฎาคม 2569",
   sales:[{category,amount,exc,vat}], expenses:[{category,amount,...}],
   payments:{เงินโอน,เงินสด,...}, menu:[{name,category,qty,amount}],
   zones:{โซน:ยอด}, voids:{cancelled,deleted,returns,discount}, bills:89 }]
```

**`saisang_data.json`** (รายเดือน — Dashboard อ่านตัวนี้):
```
[{ period, total_sales, total_expenses, net_profit,
   expense_categories[], sales_categories[], payment_methods[], payment_days[],
   daily_totals:[{date,sales,expenses,profit,food,raw,bev,bevc,bills}],
   menu_items[], zone_sales[], voids{}, recon{} }]
```
`daily_totals` = หัวใจของกราฟรายวัน/สัปดาห์ (food=ยอดขายอาหารไม่รวมญี่ปุ่น/เครื่องดื่ม, raw=ต้นทุนวัตถุดิบ, bev=ยอดขายเครื่องดื่ม, bevc=ต้นทุนเครื่องดื่ม)

## 6. ⚠️ Gotchas สำคัญ (ห้ามลืม)

1. **ชื่อไฟล์รายงาน POS = วันเนื้อหา +1** (POS พิมพ์เช้าวันรุ่งขึ้น) → suffix = `YYYY`+เดือน+วัน ของ (วันธุรกิจ+1) · โค้ด backfill map ด้วย offset นี้
2. **มิถุนายน = Excel** (รัน `juneUseExcel` ปลดออกจาก POS แล้ว) → POS ห้ามแตะ June อีก
3. **หนึ่งเดือน = หนึ่งแหล่งข้อมูล** (POS ออโต้ **หรือ** Excel อัปมือ) อย่าให้ชนกัน
4. **Google OCR มี rate limit** — backfill ข้ามวันที่เก็บแล้วโดยไม่ OCR + retry พัก 60 วิ (สูงสุด 2 ครั้ง) · อย่ากดรันรัวๆ
5. **Dashboard กันแคช** — `fetch(...&_=Date.now(), {cache:'no-store'})`
6. **แจ้งเตือนใช้ OA2** (`LINE_ADMIN_PUSH_TOKEN`) เพราะกลุ่ม management มีแต่ OA2 · OA1 push เข้าไม่ได้ (400)
7. **อย่ากด "บันทึกขึ้น Drive"** ตอนจอโหลดข้อมูลไม่ครบ → ทับข้อมูล POS
8. รายงาน POS **ไม่มี** ชื่อพนักงาน/รายชั่วโมง → ทำ peak-hour / จับทุจริตรายคน **ไม่ได้**

### 6.1 🩸 ตระกูลบั๊ก "ยอดขายผิดแบบเงียบ" — เจอ+แก้ 19 ส.ค. 2026 (อ่านก่อนแตะตัวอ่านใบ POS)

ยอดขาย 5 วันต่ำกว่าความจริงรวม **~172,000 บาท** โดยไม่มีสัญญาณเตือนใดๆ ต้นเหตุมี 4 อย่างซ้อนกัน:

| # | อาการ | ต้นเหตุ | แก้ยังไง |
|---|---|---|---|
| 1 | หมวดหายทั้งหมวด (11/08: 33,370 แทน 103,637) | ใบที่คน export ย้อนหลังเป็น**ฟอร์แมตอังกฤษ** (`Sales Report`/`From 11`/`Category`/`Grand Total`) แต่ตัวอ่านเขียนไว้รองรับใบไทยของระบบ → ไล่เลขไปชนบรรทัดหัวกระดาษแล้วข้ามหมวดนั้นทิ้ง | เพิ่มคำหัว/ท้ายกระดาษอังกฤษใน regex `junk` + ตัดหัวตาราง `Total(Inc. tax)` + ใช้ `Grand Total` เป็นขอบเขตหมวดสุดท้าย |
| 2 | หยิบเมลผิดใบ (31/07 ไปเจอใบเสร็จ **Grab**) | จับคู่แค่ "วันที่ในหัวเรื่องตรง + มีไฟล์แนบ" | บังคับว่าเมลนั้นต้องมีไฟล์ `SaleReport` จริง |
| 3 | **ลงผิดวัน → ทับข้อมูลจนหาย** (31/07 = 118,449 กลายเป็น 0) | **เมลที่ระบบส่งเองตอนตี 1 ใช้ "วันที่ส่ง" เป็นหัวเรื่อง = วันทำการ + 1** · ของเดิมเจอเนื้อในไม่ตรงหัวเรื่องแล้ว "เชื่อหัวเรื่องไว้ก่อน" | แยกเมลกลางคืน (ส่งวันเดียวกับหัวเรื่อง + ก่อน 8 โมง → ลบ 1 วัน) ออกจากใบ export ย้อนหลัง (หัวเรื่อง = วันทำการตรงๆ) |
| 4 | หาวันที่ไม่เจอ (26/07 ขึ้น "ไม่พบอีเมล") | ใบของ 26/07 อยู่ในเมลหัวเรื่อง 27/07 | ข้อ 3 แก้ให้เอง + เผื่อหาจากวันที่ในชื่อไฟล์แนบ (`_260726_`) |

**ตัวกันไม่ให้เกิดซ้ำ (อยู่ใน `_importPosOneDate_` แล้ว — ห้ามถอดออก):**
- เนื้อใน PDF บอกวันอื่น → **ปฏิเสธ ไม่บันทึก** (เดิมเขียนทับ)
- แกะยอดขายได้ 0 แต่ของเดิมมีข้อมูล → **ปฏิเสธ ไม่บันทึก**
- ใบเสริม (Payout/Balance/ลูกค้า) OCR พัง → คงข้อมูลเดิมไว้ ไม่ทับด้วยค่าว่าง + ไม่ทิ้งทั้งวัน
- ชน rate limit → หยุดทั้งรอบทันที + พิมพ์ `DATES` ของวันที่เหลือ (เดิมไล่บดจนชนลิมิต 6 นาที)

**บทเรียนที่ใช้ตรวจได้ทั่วไป:** ยอดขาย (ใบขาย) กับเงินรับ/โซน (ใบ BalanceCashDrawer) เป็น**คนละไฟล์** — ถ้าตรงกันคือยืนยันข้ามแหล่งแล้ว เชื่อได้ · ร้านนี้ยอดขาย ≈ เงินรับ เกือบเป๊ะทุกวัน ต่างกันมากเมื่อไหร่ = ผิดปกติ ต้องสืบ

## 8. สรุปข้อมูลธุรกิจ (วิเคราะห์ล่าสุด)

- **ร้านเท่าทุน** (cost ratio ~100%) — แต่รวม "ชำระหนี้ UOB" (หนี้) + "CEO" (ค่าแรงเจ้าของ) ในต้นทุน → กำไรดำเนินงานจริงดีกว่านั้น
- **เครื่องดื่ม ~57% ของยอดขาย · margin 46%** (ปกติของบาร์เบียร์/เหล้าขวด) → เล่นที่ราคา+ปริมาณ · โปร "5+1" กินกำไร
- **3 คืนขาดทุน (จ/พ/พฤ) ~86k/เดือน** = จุดลดต้นทุนใหญ่สุด (ค่าแรงวันธรรมดาไม่ยืดหยุ่นตามยอด)
- **เสาร์ cost ratio 95%** (สูงผิดปกติเทียบศุกร์ 73%) — ต้นทุนเสาร์มีอะไรเกิน
- **อาหารญี่ปุ่น = ฝากขาย** (กำไร 15% จ่ายคืนร้านญี่ปุ่น = หมวด "เก็บออมญี่ปุ่น")

## 9. งานค้าง

- 🐞 **ตัวแกะ "รายเมนู" (`parseSaleItems_`) เพี้ยน ±5%** — พบ 19/08/26: 31/07 ยอดขาย 129,277 (ยืนยันด้วยเงินรับ+โซน) แต่รายเมนูรวมได้ 136,388 · 12/08 กลับต่ำกว่า 1,577 → **กระทบเฉพาะหน้า "เมนูขายดี" ยอดเงิน/รายงานการเงินไม่กระทบ** · `checkSaleTotals` จะขึ้นเป็นหมายเหตุ 🔵 พร้อมกำกับว่าห้ามอ่านใหม่ (อ่านกี่รอบก็ได้เลขเดิม)
- 🔎 **16/07 ยังไม่ได้ตรวจ** — ยอดขาย 76,415 แต่เงินรับ 92,653 (ต่าง 16,238) · วันอื่นยอดขาย ≈ เงินรับ เกือบเป๊ะ จึงน่าสงสัยว่าโดนบั๊กลงผิดวัน · กู้ด้วย `var DATES = ['2026-07-16'];` (ปลอดภัยแล้ว มีตัวกันทับข้อมูล) ถ้าได้ ~92,6xx = เจอเพิ่มอีกวัน ถ้าได้เท่าเดิม = ปกติ (ลูกหนี้มาจ่าย)
- 🧾 **ต้นทุนเมนู** → ทำ Menu Engineering (ดาวเด่น/ตัวถ่วง) — รอเจ้าของส่งต้นทุน
